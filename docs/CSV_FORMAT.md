# Формат CSV для импорта расписания

Документ описывает контракт CSV, который понимает `ScheduleCsvParser`
(`schedule-import-parser-core/src/main/java/ru/parser/ScheduleCsvParser.java`).

Импорт идёт через:

- **Ручной**: `POST /api/import/csv` (multipart, `ADMIN`).
- **Автоматический**: scheduler в `schedule-service` тянет CSV по `auto_import_settings.source_url` (обычно — публичный экспорт Google Sheets).

---

## 1. Общая структура

CSV — широкая таблица: **строки = группы**, **колонки = даты**.

| | дни недели | дни недели | дни недели | … |
|---|---|---|---|---|
| **строка 0** | `пн` | `вт` | `ср` | … |
| **строка 1** | `1.янв.` | `2.янв.` | `3.янв.` | … |
| **строка 2..N** | ячейка | ячейка | ячейка | … |

- **Строка 0** — дни недели (`пн/вт/ср/чт/пт/сб/вс`). Парсер их не использует, но они должны быть.
- **Строка 1** — даты в формате `<день>.<месяц>.` (например `27.апр.`, `1.янв.`, `5.мая`). Месяц — русское сокращение, парсер маппит в `java.time.Month` через `DateParser.MONTHS`.
- **Колонка 0** — заголовок группы.
- **Все остальные ячейки** — содержимое дня для группы × даты.

Пустые ячейки игнорируются. Ячейки в колонках без даты в строке 1 — игнорируются с предупреждением в логе.

---

## 2. Заголовок группы (колонка 0)

Строка вида:

```
гр. <номер> [(<пометка>)]
<location>
```

Многострочный текст, **разделитель строк внутри ячейки — `\n`** (CSV-кавычки обязательны).

Примеры:
```
"гр. 87
А308"
```
```
"гр. 174 (резерв НС АС)
Б202"
```

Парсер:
- `code` = первая строка целиком (`"гр. 87"`, `"гр. 174 (резерв НС АС)"`).
- `location` = вторая строка, если есть (`"А308"`).

---

## 3. Ячейка дня

Многострочный текст. Парсер бьёт по `\n` и читает построчно, поддерживая state:
- активный `courseCode`,
- активный `pendingInstructor` (имя инструктора, увиденное на отдельной строке),
- активный `pendingTitle` (накопленное название из строк без длительности),
- режим `selfStudy` (после маркера `СП`),
- режим `inAssessment` (после строки с assessment-title).

### 3.1 Поддерживаемые токены

| Токен | Пример | Поведение |
|---|---|---|
| **Course code** | `OE00`, `I&C02`, `CS01:` | Регэксп `^[A-Z&]{1,5}\d{2}$` (с опц. `:` в конце). Сохраняется как `day.meta.courseCode` и тянется как «активный код» дальше по дню/группе |
| **`СП`** | `СП` | Включает `selfStudy` режим — все следующие занятия будут типа `SELF_STUDY` |
| **Имя инструктора (отдельная строка)** | `Меняйло` | Запоминается как `pendingInstructor` для следующей строки с длительностью. Парсер знает фиксированный список ФИО — см. §5 |
| **Assessment-title** | `Intermediate Examination`, `Промежуточный контроль (8ч)`, `Intermediate Examination (пересдача)` | Создаёт занятие с `type = ASSESSMENT`. Все последующие строки `<Имя> (Nч)` добавляются как инструкторы того же контроля |
| **Простой текст без длительности** | `System of chemical reagents preparation (KBD-1)` | Накапливается в `pendingTitle` (несколько подряд → конкатенируются через пробел). Применяется к следующему занятию с длительностью |
| **Строка с длительностью** | `Бунда (4ч)`, `Title text (2ч)`, `(8ч)` | См. ниже два формата |

Длительность распознаётся регэкспом `\((\d+)\s*ч\)` — `(4ч)`, `(4 ч)`, `(8ч)`. Без `ч` не считается.

### 3.2 Два формата записи занятия

#### **Формат A (legacy, доминирующий в старых выгрузках)**

Имя инструктора **до** строки с длительностью:

```
I&C02
Алексеев
I&C02.01.10 Software and Hardware Complex of Electronic Part... (4ч)
Алексеев
I&C02.01.06 Power Unit Control Posts... (1ч)
```

Парсер:
- `Алексеев` → `pendingInstructor`.
- Строка с `(4ч)` без инструктора в тексте → создаёт `Lesson(title="I&C02.01.10 ...", lecturer="Алексеев", durationHours=4, type=LECTURE)`.

#### **Формат B (встречается в новых выгрузках — гр.174 и т.п.)**

Имя инструктора **внутри** строки с длительностью, название — на следующей строке:

```
CH03
Меркель (2ч)
System of chemical reagents preparation (KBD-1)
Меркель (3ч)
Primary coolant treatment system (KBF)
СП
Меркель (1ч)
Liquid radioactive waste storage system (KPK)
```

Парсер:
- `Меркель (2ч)` → length-line, в тексте найден инструктор `Меркель`, остаток (после удаления имени) пустой → **lookahead на следующую plain-text строку как заголовок**.
- Поглощает `System of chemical reagents preparation (KBD-1)` как `title` и помечает строку «съеденной».
- Создаёт `Lesson(title="System of chemical reagents preparation (KBD-1)", lecturer="Меркель", durationHours=2, type=LECTURE)`.
- Дальше `Меркель (3ч)` + `Primary coolant treatment system (KBF)` — то же.
- `СП` → `selfStudy = true`.
- Следующие занятия будут типа `SELF_STUDY`.

#### **Многострочное название (Формат A с разрывом)**

```
Трушейкин
Annulus ventilation systems (KLC10÷40,01÷05)
Intershell leakage containment system (KLC11÷41) (2ч)
```

Парсер:
- `Трушейкин` → `pendingInstructor`.
- `Annulus ventilation systems (...)` — нет длительности → `pendingTitle`.
- `Intershell ... (2ч)` — длительность есть, инструктор в тексте не найден → склеивает `pendingTitle + " " + текст` → `title = "Annulus ventilation systems (KLC10÷40,01÷05) Intershell leakage containment system (KLC11÷41)"`.

### 3.3 Assessment

Любая строка, в которой содержится подстрока (case-insensitive) одного из ключей:

```
Intermediate Examination
Промежуточный контроль
Entry Level Test
Examination
Entermidiate examination   (опечатка из реальных данных, оставлена для совместимости)
```

— создаёт `Lesson(type=ASSESSMENT, title=<строка без длительности>)`. Парсер разрешает суффиксы:

```
OE00
Intermediate Examination (пересдача)

Бращенко (3ч)
Костылев (3ч)
Климов (3ч)
```

Результат: **одно** занятие с `title="Intermediate Examination (пересдача)"`, `type=ASSESSMENT`, `durationHours=3`, `lecturers=[Бращенко, Костылев, Климов]`.

Альтернативно можно с длительностью прямо в строке:

```
T02
Intermediate examination (8ч)
Климов (8ч)
Алексеева (8ч)
```

→ `title="Intermediate examination"`, `type=ASSESSMENT`, `durationHours=8`, `lecturers=[Климов, Алексеева]`.

## 4. Активный course code

Если в ячейке нет course-code, парсер берёт **последний увиденный** code предыдущих ячеек (по той же группе). Это имитирует поведение Google Sheets, где код в одной ячейке часто относится к нескольким соседним дням.

```
[E03]  ← ячейка 1: только code и занятия
[ ... только инструктор+название без code ...]  ← ячейка 2: courseCode = E03 (унаследован)
```

Если у `Day` так и не появился `courseCode` — день **не сохраняется**.

## 5. Список известных инструкторов

Распознавание ФИО на отдельной строке работает по фиксированному списку (см. константу `INSTRUCTORS` в парсере):

```
Бращенко, Волкова, Майстренко, Мухамбеталин, Трушейкин, Брянский,
Коновалов, Костылев, Алексеева, Голубенко, Гонтов, Иванов,
Кадчик, Канищев, Ким, Иванов С, Смирнов, Климов, Павленко,
Алексеев, Виноградов, Гончаров, Корепанова, Меняйло, Расписенко,
Шорохов, Вакуров, Бунда, Вишняков, Егоров, Коваленко, Баринов,
Киблер, Левковицкая, Фарейтор, Чирков, Климова, Салимжанова,
Ивахно, Короткова, Меркель, Кузнецов Д, Харламова, Загузин,
Лошманов, Name
```

> ⚠️ При появлении нового преподавателя — нужно добавить ФИО в этот список и пересобрать `schedule-service`.
> Будущая итерация: подтягивать список из `users` (где `can_teach=true`), чтобы не править код.

После импорта `Lesson.lecturer` (строка) маппится на `User` по совпадению `User.fullName` — это создаёт связь `lesson_instructors`.

## 7. Ограничения и крайние случаи

- ❌ **`(8)` без `ч`** — не считается длительностью. В реальных данных встречалось как опечатка `Голубенко (8)`. Будет проигнорировано.
- ⚠️ **Многострочные ассесмент-заголовки** (`Intermediate\nExamination` на двух строках) распознаются плохо. Если возможно — держи название одной строкой.
- ⚠️ **Формат A и B в одной ячейке** работают, но порядок важен — pendingInstructor / pendingTitle сбрасываются при создании занятия.
- ⚠️ **Дубликаты инструкторов** — `findInstructors` находит все совпадения подстроки. Если ФИО одного — префикс другого (`Иванов` / `Иванов С`), распознавание становится неоднозначным. Сейчас выбирается первое совпадение из `Set.of(...)` (порядок не гарантирован). Будущее улучшение — точный matcher по границам слов.

## 8. Тесты

`schedule-import-parser-core/src/test/java/ru/parser/ScheduleCsvParserTest.java`:

- `parse_ignoresNonEmptyCellsWithoutDateHeader` — ячейки в колонках без даты → не сохраняются.
- `parse_treatsEntryLevelTestAsAssessmentInsteadOfNamelessLecture` — `ELT00 / Entry Level Test / Name (8ч)` → ассесмент.
- `parse_handlesInstructorFirstFormat` — Формат B (гр.174).
- `parse_handlesAssessmentWithSuffixAndMultipleInstructors` — гр.87 с `(пересдача)` и тремя инструкторами.
- `parse_handlesCourseCodeWithTrailingColon` — `CS01:` распознаётся как course code.

```bash
mvn -B -pl schedule-import-parser-core test -Dtest=ScheduleCsvParserTest
```
